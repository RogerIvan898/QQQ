# Дизайн

## Контекст

- Карманные карты везде типизированы как пара: `Player['hand']: [Card, Card] | null`, `YOUR_CARDS.cards: [string, string]`, debug-карты и вскрытия на шоудауне приводятся к `[Card, Card]`.
- В `entities/room` уже есть `RoomGame = 'nlh'` и словарь `GAME_LABELS` на карточке комнаты — у варианта есть естественное место.
- `features/equity` оценивает руки битовыми масками (`addCardToState`, `scoreHandState`), воркер на каждую раскрутку считает «борд + 2 карманные» (`scoreBoardWithHoleCards`). `bestFiveCards` и `handCategoryLabel` делают одну оценку всех карт («лучшие 5 из N»), что для Омахи неверно.
- `PlayerCards` анимирует ровно два слота (`showFirst` / `showSecond`), размер берёт из `--card-width` от ширины стола.
- Панель ставки уже ограничивает сумму `ALLOWED_ACTIONS.maxRaise`; лимит пота считает сервер.

## Цели / Не цели

**Цели:**
- Один путь кода для обоих вариантов, параметризованный вариантом и числом розданных карт.
- Корректная оценка Омахи по правилу 2+3, проверенная тестами против полного перебора.
- Equity в пределах бюджета 1 с на телефоне среднего уровня, в существующем воркере.

**Не цели:**
- Расчёт лимита пота, сайд-потов и победителей на клиенте (источник истины — сервер).
- Hi-Lo, 5-карточная PLO, смешанные игры.

## Решения

### Источник варианта
Вариант берётся из комнаты в списке (`game`, по умолчанию `nlh`) и передаётся в подключение к игре при входе; поле `game` в `HAND_STARTED`, если сервер его пришлёт, имеет приоритет. Для стола вариант хранится в сторе `$gameVariant` в `entities/game`.
- Альтернатива: определять по числу розданных карт. Отклонено как основной источник (карты соперников скрыты до шоудауна, а подписи и лимиты должны быть верны с первого кадра), но используется как проверка в dev.

### Карманные карты как список
`Player['hand']` становится `readonly Card[] | null` (так же debug-карты, вскрытия, история рук). Компоненты читают `hand.length`, а не предполагают две карты.
- Альтернатива: объединение `[Card, Card] | [Card, Card, Card, Card]`. Отклонено: на практике безопасности не добавляет, а типы шумнее.

### API оценки с учётом варианта
`features/equity` экспортирует `bestFiveCards(variant, hole, board)` и `handCategoryLabel(variant, hole, board)`. Для `nlh` остаётся текущий путь с одной оценкой; для `plo` перебираются 6 пар карманных × 10 троек борда (при 3–4 картах борда — соответствующие тройки), берётся лучший счёт, а пятёрка выбирается из выигравших пары и тройки.
- Альтернатива: табличный оценщик Омахи. Отклонено: большие таблицы раздувают бандл, а 60 оценок на битовых масках дёшевы.

### Equity Омахи в том же воркере
В запрос воркера добавляется `variant`. На каждую раскрутку состояния троек борда строятся один раз, к каждой тройке добавляется каждая из 6 пар карманных карт игрока (2 `addCardToState` + 1 `scoreHandState`). Выбор между точным перебором и выборкой взвешивается числом оценок на раскрутку (×60 для PLO), поэтому мультипот PLO на префлопе считается выборкой; размер выборки для PLO подбирается через `scripts/bench-equity.ts`, чтобы держаться в ~300 мс в воркере. Отмена работает как сейчас (занятый воркер завершается при новом запросе).
- Альтернатива: несколько воркеров параллельно. Отложено — нужно, только если бенчмарк не уложится в бюджет.

### Раскладка четырёх карт на месте
`PlayerCards` рисует N слотов по длине руки (рубашки — по числу карт варианта) с перекрытием, чтобы четыре карты занимали примерно в 1,6 раза больше ширины, чем две; крупные карты игрока сохраняют текущий размер карты и слегка раскрываются веером. Тайминг раздачи сдвигается по индексу слота с текущими задержками на карту. Containment места (`contain: layout style`) остаётся, так что более широкие руки не пересчитывают раскладку всего стола.
- Альтернатива: два ряда по две карты. Отклонено: более высокие места сталкиваются с бейджами ставок на компактной раскладке.

### Подпись пресета лимита пота
Верхний пресет в панели ставки называется «Пот», когда `variant === 'plo'` и `maxRaise` меньше стека плюс уже поставленного, иначе «Олл-ин». Расчёта пота на клиенте нет.

### Мок-сервер
В `mocks/poker` появляется стол PLO: раздача 4 карт, ранжирование Омахи на новом оценщике, лимит пота в `maxRaise` для ботов и игрока. Мок-код, как и сейчас, не попадает в продакшн-сборку.

## Риски / Компромиссы

- [Более широкие места перекрываются на телефоне при 9 игроках] → перекрытие и веер настраиваются на 375 px; масштаб мест уже зависит от ширины стола; проверить все позиции на компактной раскладке.
- [Equity PLO слишком медленный на слабых Android] → выборка с учётом стоимости оценки, отмена в воркере, бенчмарк как шаг в задачах.
- [Контракт бэкенда не готов] → без `game` клиент считает комнату `nlh`; PLO доступна только через мок, пока сервер не начнёт отдавать комнаты `plo`.
- [Старая история рук в localStorage с парами карт и без варианта] → читается как `nlh`; `Card[]` принимает её без изменений.
- [Переводы] → новые строки («PL Omaha», «Пот», подпись фильтра) идут через Lingui с переводом на русский.

## План миграции

Изменение только на клиенте и обратно совместимо: пока сервер не присылает `game: 'plo'`, для игроков ничего не меняется. Выкатка — бэкенд начинает показывать комнаты PLO. Откат — бэкенд перестаёт их показывать; релиз клиента не нужен.
